# 项目记忆分层与 Skill 自动发现

## 使用入口

- 聊天页顶部选择已注册项目，或点击“选择项目文件夹”。切换项目会新建会话，不把旧对话内容带入另一个项目。已有会话的项目归属固定。
- “设置 → 记忆”与原侧栏入口共用管理页面：用户偏好跨项目共享，普通记忆只在选中项目使用；支持编辑、删除、归档和恢复。旧格式 Core 原文也可编辑，结构化偏好不会被覆盖。
- “设置 → 扩展能力 → Skills”可打开自动发现开关、审核待安装草稿、查看来源任务、修改步骤/注意事项/验证方法并预览最终文件。创建候选可改为用户级；更新候选保留原目标作用域。
- 聊天中的“发现一个可复用流程”卡片从已保存候选恢复。“稍后处理”仅隐藏卡片，不拒绝或删除草稿。
- 关闭自动发现不会禁用已安装 Skills，也不影响“从当前任务生成 Skill”。拒绝/删除后的流程有抑制记录，可恢复推荐。分析失败可手动“重新分析”。

## 隔离与存储

项目 ID 根据规范化、已存在的绝对路径生成并保存在 SQLite。Conversation、Run、Task 保存项目归属。每个 Run 创建独立工具执行器和子 Agent 工具图，文件工具使用项目工作目录；用户模型配置、审批规则和电脑操作锁继续共享。

默认工作区沿用已有存储路径；新项目的数据位于数据库同级 `projects/<project_id>/`。用户 Core 和用户级 Skills 跨项目共享。每个项目独立管理最多 25 条 active 普通记忆；Core 上限为 2,000 token。Markdown 是记忆权威存储，检索索引故障只会降级检索。

偏好按稳定 key 更新。后台偏好提取只读取当前用户消息；项目整理必须有用户原话或成功工具结果中的原文证据，保存项目接口/决策类型及来源。临时状态留在 Task/Trace。手动编辑使用版本校验；旧 Run 或后台结果不能覆盖后来的人工作业。

删除普通记忆是移入项目记忆的 `deleted/`，不再召回，保留原文件以便恢复。正式 Skill 编辑保留资源文件及可选 YAML 字段。Run 使用启动时冻结的 Skill 描述和正文；编辑与启停在下一次 Run 生效。

## 自动发现

任务完成处理由 Desktop 与 CLI 共用，另有后台恢复检查。每个项目串行分析最近 50 个已完成 Task；仍在运行中的 Run 对应任务会等待 Trace 完成。少于 5 个 Task 不调用模型，5 个任务也必须组成至少 5 个不同 ID 的相似流程，并有真实成功工具执行证据。

先分析任务摘要，再读取执行证据蒸馏流程。重试、多个工具调用和同一个 Task 的多轮会话不增加计数。历史任务保持可参与后续窗口；未满足阈值不会永久排除。已有 Skill 能覆盖时不创建；改进生成待审核更新候选。

候选、扫描窗口、重试次数、隐藏状态和流程抑制记录均持久化。重复触发合并；同一窗口完成后不重复扫描。失败最多自动重试配置的次数，重启仍保留状态；也可手动重新分析。先保存再通知，重连重新查询持久化数据。

审核接受前写入持久化审核意图，再原子写正式 Skill，最后标记已接受。写入后进程中断可在重启/重试时补齐状态，不能重复安装。更新候选校验目标文件版本，拒绝覆盖期间的人为修改。自动生成只产生流程指令，不生成或执行额外脚本。

## 迁移与验证

Host 初始化前将旧数据库、Tasks、Memory、项目 Skills 与候选数据备份到数据库同级 `migration-backup-v2/`。旧会话、Run、Task、普通记忆与项目候选幂等归入原 Host 工作目录对应的默认项目；用户级 Skill 目录不迁移。原文件/首次备份保留，不根据文本猜测其他项目。

验证命令：

```powershell
cd backend
.venv/Scripts/python.exe -B -m pytest tests/offline -q
cd ../desktop
npm test
npm run build
```

专项测试在 `backend/tests/offline/test_project_memory_learning.py`，覆盖并发服务隔离、真实文件工作目录、RPC 审核管理链路、后台过期保护、5 次阈值、有效证据、拒绝抑制、审核中断恢复、最终预览与资源保留、迁移和重启。前端测试覆盖项目选择、发现卡片、持久化审核表单、来源展示和 RPC 作用域/版本参数。

自动化验证使用离线模型替身，不代表真实模型的流程识别质量或召回效果已经评估。Electron 原生目录选择窗口与真实模型联机生成仍需人工体验验收。
